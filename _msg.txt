Evaluate open-source Jev alternatives; keep Jev as the primary provider

Investigated the seven projects named in the DataCamp "Open-Source TypeSafe Jev
Alternatives" article and verified each directly via the GitHub API and
Hugging Face rather than trusting the write-up.

The projects are real and several ship genuine weights (Kev 0.8B-27B on
Qwen3.5, Laya, NanoJev, Rizzo Flow). They are still not adopted as the primary
provider, for reasons recorded in docs/decisions/0003:

- they would change the subject of the research question, which is whether a
  fast typed decision model works as a decision layer;
- this machine (GTX 1650, 4GB VRAM) cannot run the 4B checkpoint the projects
  themselves recommend, so "free" means slow enough to defeat the low-latency
  premise;
- calibration is the entire value of a decision layer, and Rizzo Flow schema
  admits a probability_status of uncalibrated_conditional_option_scores or
  temperature_scaled_requires_held_out_validation;
- the popularity signals are unreliable: repos days old carry 4.5k-7.6k stars,
  and one HF model shows 4,246 likes with 0 downloads.

Kev is recorded as the preferred baseline for the future evaluation harness,
since it publishes weights and claims the TypeSafe System One API shape. It is a
baseline for measurement, not a production fallback.

Jev via OpenRouter stays primary: it is already integrated and verified up to
billing, and costs $0.042 per million input tokens. The blocker is credits, not
architecture.
